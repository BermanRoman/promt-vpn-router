# Локальное состояние дела

`scripts/case.py` работает офлайн на Python 3.9+ из стандартной библиотеки.

Он не исполняет команды инфраструктуры, не подключается к серверам и не читает содержимое файлов доказательств или секретов.

Ручная запись `pass` — заявление оператора, а не автоматическое доказательство истинности результата.

`check` проверяет структуру, полноту, зависимости, наличие файлов и минимальную записанную длительность WAN.

## CLI

```sh
python3 scripts/case.py init /absolute/local/path/new-case
# Отредактировать new-case/project.json локально и создать обезличенные evidence-файлы.
python3 scripts/case.py status /absolute/local/path/new-case
python3 scripts/case.py record /absolute/local/path/new-case scope_authorized pass --note 'Scope approved locally' --evidence evidence/intake.txt
python3 scripts/case.py check /absolute/local/path/new-case
python3 -m unittest discover -s scripts -p 'test_case.py'
```

Родительский каталог должен существовать; `init` отказывается использовать уже существующий каталог.

На POSIX каталог дела получает права 0700, файлы состояния — 0600; дополнительные файлы доказательств защищает оператор.

`record` заменяет текущую запись одного gate, сохраняя остальные; журнал прежних записей не ведётся.

Для повторной проверки после изменения инфраструктуры оператор вручную устанавливает затронутые проверки в `unknown` и повторяет испытания.

`check` не обнаруживает устаревание доказательств или незаявленные изменения инфраструктуры.

Коды возврата: 0 — успешная операция либо полное дело, 1 — неполное/неуспешное дело при `check`, 2 — ошибка аргументов, структуры, зависимости либо доступа к файлу.

`status` показывает только этапы и количество записей; код 0 у `status` не означает готовность дела.

## project.json

Версия схемы — `schema_version: 1`; разрешены только поля из шаблона `assets/project.example.json`.

`router` — явный boolean; исходный профиль использует роутер.

`exit_mode` — `single-exit` по умолчанию либо `split-exit` при отдельном требовании специального выхода.

`adfilter_enabled` необходимо установить в `true` или `false`; исходное `null` блокирует обработку дела.

`provider_defaults` содержит только подписи исходного набора: Timeweb для домена/DNS, is*hosting Serbia для панели, VDSINA Netherlands для основного выхода, Cudy WR3000S v1 для роутера.

Эти подписи не подтверждают наличие услуг, аппаратную ревизию, совместимость, подписанную прошивку или скорость VPN; гигабитные порты не гарантируют гигабитный VPN.

`endpoints` — список объектов только с `role` и `host`; документационные адреса и домен шаблона заменяются локально после обследования.

`secret_file_refs` — список путей к локальным файлам секретов; helper не открывает их и не проверяет содержимое.

Пароли, токены, UUID, URL подписок и SSID в схеме не предусмотрены; никогда не записывайте их в `case_name`, `note`, endpoint или доказательства.

## state.json и проверки

Состояние содержит `schema_version: 1` и объект `records`, ключами которого служат gate ID.

Каждая запись содержит `status` (`pass`, `fail`, `unknown`, `skipped`), список `evidence`, обезличенный непустой `note`, `duration_seconds` (обычно null) и UTC `recorded_at`.

`pass` и `fail` требуют хотя бы одного существующего обычного файла; путь должен быть относительным внутри дела без `..`, включая разрешённую цель symlink.

Сами `project.json` и `state.json` не считаются доказательствами.

Рекомендуемый каталог — `evidence/`; исходные секретные логи предварительно обезличиваются отдельным процессом.

Этапы последовательны; новый `pass` разрешён только после полного завершения всех предыдущих этапов.

`fail`, `unknown`, отсутствующая запись и невалидное доказательство блокируют завершение.

Без роутера каждый gate этапов `router_selection`, `router_recovery`, `router_wan`, `router_vpn` требует явного `skipped` с причиной.

При `single-exit` явного пропуска требуют проверки специального выхода и его изоляции; при выключенной фильтрации — фильтрация и обновление правил.

Остальные обязательные проверки пропускать нельзя; `cutover` и итоговая приёмка нужны также для клиента без роутера.

| Этап | Gate ID и смысл доказательства |
|---|---|
| intake | `scope_authorized`, `requirements_confirmed`: полномочия и требования |
| inventory | `current_inventory`, `existing_operations_reviewed`: актуальные узлы и действующие эксплуатационные механизмы |
| router_selection | `router_exact_revision`, `router_flash_compatibility`, `router_signed_firmware`: доказательство точной ревизии конкретного экземпляра, совместимости платформы/профиля/комплекта прошивки и проверки подписи образа до рекомендации покупки и проектирования |
| design | `topology_approved`, `rollback_plan`: согласованная схема и исполнимый откат |
| access | `ssh_hostkey_independent`: host key проверен по независимому доверенному каналу; `ssh_authentication`: отдельная проверка аутентификации |
| servers | `backups_verified`: проверенные резервные копии; `server_core`: доказательство ядра сервера; `special_exit_isolation`: серверное ограничение специального выхода |
| client_pilot | `actual_client_ru_direct`, `actual_client_foreign_exit`, `actual_client_special_exit`: наблюдение с реального клиента; `failed_special_closed`: отказ специального выхода закрывает путь; `other_user_denied`: чужой пользователь не проходит; `adfilter`, `rule_update`: фильтрация и работающее обновление правил |
| router_recovery | `router_recovery_link`, `router_backup_restore`: действующий путь восстановления и резервная копия/восстановление до прошивки |
| router_wan | `wan_real_isp`: реальное подключение к ISP, а не временный uplink; `wan_stable`: не менее 300 секунд; `wan_dns`, `wan_tls`, `wan_mtu`: фактические DNS/TLS/MTU до VPN |
| router_vpn | `router_ru_direct`, `router_foreign_exit`, `router_special_exit`, `router_failed_special_closed`, `router_other_user_denied`, `router_adfilter`, `router_rule_update`: повторение проверок с реального LAN-клиента через роутер |
| cutover | `cutover_authorized`, `cutover_rollback_ready`, `cutover_actual_path`: разрешение, готовность отката и подтверждение действующего пути |
| acceptance | `actual_client_acceptance`, `recovery_acceptance`: итоговая проверка реального клиента и восстановления |
| handover | `handover_limits`, `handover_operations`, `handover_accepted`: известные ограничения, обслуживание и передача владельцу |

Пример записи длительности: `record CASE wan_stable pass --note 'Real ISP WAN observed for 300 seconds' --evidence evidence/wan.txt --duration-seconds 300`.

Серверная проверка `server_core` не заменяет клиентские доказательства; числовая длительность также остаётся ручным утверждением.

Этап `router_selection` следует сразу за `inventory` и блокирует `design`, пока все его обязательные проверки не закрыты.

До рекомендации покупки требуется доказательство аппаратной ревизии конкретного экземпляра у продавца: например, обезличенное фото этикетки либо подтверждение маркировки конкретной партии.

Название модели в карточке товара не подтверждает ревизию; если продавец не может подтвердить ревизию доступного экземпляра или товар отсутствует, рекомендация покупки остаётся заблокированной.

Для уже принадлежащего владельцу устройства ревизию устанавливают по его собственной этикетке.

Helper не управляет покупкой или прошивкой: оператор обязан закрыть `router_selection` до рекомендации покупки, затем весь набор `router_recovery` до любых действий прошивки, а действующий `router_wan` — до запуска VPN на роутере.

Параллельная запись несколькими процессами не поддерживается; храните дело локально вне публичных и синхронизируемых каталогов.
